- Emit one uncompressed, well-formed `<mxfile>` with one `<diagram>`, one `<mxGraphModel adaptiveColors="auto">`, and one `<root>`. Never emit XML comments, markdown fences, prose, a compressed diagram payload, or `compressed="true"`.
- The first structural cells must be `<mxCell id="0"/>` and `<mxCell id="1" parent="0"/>`. Every id must be unique. Every other cell needs a valid parent: the default layer, another layer, or its actual container.
- A content cell is either `vertex="1"` or `edge="1"`, never both. Every planned vertex needs `mxGeometry` with nonnegative x/y/width/height. Every connected edge needs valid source and target ids plus an expanded `<mxGeometry relative="1" as="geometry"/>` child; never self-close an edge cell.
- Use every plan key as the cell id and every plan slot exactly. Do not recalculate, narrate, verify, or adjust the approved geometry. The server owns final deterministic layout and canvas sizing.
- Style strings are case-sensitive semicolon-separated tokens with no spaces around `=`; use `0`/`1` for booleans and prefer a trailing `;`. Prefer known draw.io properties and semantic shapes. For non-rectangular shapes set the matching perimeter when needed: ellipse, rhombus, triangle, hexagon, parallelogram, trapezoid, callout, backbone, center, or step.
- Include `whiteSpace=wrap;html=1;` for labels. XML-escape `&`, `<`, `>`, and quotes inside attributes. Use `&#xa;` or escaped `<br>` for line breaks, never a literal `\n`. Use `fontStyle` when the entire label has one emphasis; use escaped HTML only for partial formatting and do not apply both for the same effect.
- Use one edge family throughout each diagram unless the type guide names a meaningful exception: orthogonal for structured flows and architecture, straight for UML class/sequence and direct links, entity-relation for ER, curved for mind maps. Keep edge labels short. Apply dashed lines, colors, width, and arrowheads consistently; add a legend when several visual semantics coexist.
- Do not hand-route connected edges. Do not emit waypoint arrays or `exitX`, `exitY`, `entryX`, or `entryY` overrides unless the approved plan requires a specific geometric attachment. Place nodes so the selected edge family can travel through reserved whitespace.
- Implement containment structurally, not by drawing a large box behind unrelated root-level children. Use `group;pointerEvents=0;` for invisible non-connectable groups, `swimlane;startSize=...;` for titled/connectable containers, or `container=1;pointerEvents=0;` for a custom non-connectable container. Children reference the container and use parent-relative geometry.
- Put an edge whose endpoints live in different containers at `parent="1"` so it is not clipped. A boundary-crossing edge may cross a container border naturally; do not add waypoints to avoid the border.
- Use flat swimlanes for one-dimensional responsibility. Use a draw.io `table`/`tableRow` hierarchy only when both actor and phase are explicit. Use nested titled containers for real nested architecture. Do not nest lanes inside a pool or table merely for appearance.
- Additional layers are parent-0 cells and should be added only for explicitly toggleable conceptual views. Later layers render above earlier ones; `visible="0"` hides a layer initially.
- Tags or custom metadata require an `<object>` wrapper. Put `id`, `label`, space-separated `tags`, custom attributes, and optional `placeholders="1"` on `<object>`; keep the wrapped `mxCell` for style, type, parent, and geometry. Use `%%` for a literal percent sign. Do this only when the plan/source explicitly requires filterable or data-bound shapes.
- Use a small accessible palette with high text contrast. Explicit light colors adapt through `adaptiveColors="auto"`; use `light-dark(light,dark)` only when automatic inversion would be unclear. Same-role objects must share shape, typography, dimensions, stroke, and color treatment.
- Before returning, ensure the root structure exists, ids and parent references are valid, every planned object appears once, edge endpoints exist, vertex and edge geometries are complete, dimensions are nonnegative, container coordinates are relative, styles are valid, HTML is escaped, and no unplanned visible object or unsupported fact was added.
