# Flowchart

## Planning

- Choose top-to-bottom for tall decision flows or left-to-right for pipelines; keep one primary reading direction.
- Model actions as process/rounded rectangles, decisions as rhombuses, inputs/outputs or documents with their semantic shapes, and explicit start/end states as ellipses.
- Each decision needs source-supported outgoing branches with short labels such as Yes/No. Merge branches at a clear convergence point when the source supports it.
- Use groups only for real subprocesses, phases, or ownership boundaries. Keep the main path visually dominant and feedback loops sparse.

## XML generation

- Use orthogonal, rounded connectors with classic arrowheads and consistent stroke. Decision branch labels belong on their edges.
- Apply the matching perimeter to decision and terminal shapes. Keep start/end visually distinct but within the diagram palette.
- Do not add manual waypoints or ports. Respect the planned whitespace between layers so loops and branches do not cross nodes.
