# Organizational chart

## Planning

- Build a top-down reporting tree from the source. Use one node per person, role, or organizational unit and preserve name/title detail only when available.
- Keep peers at the same hierarchy level and group real departments or teams. A node has one solid-line manager unless the source explicitly describes matrix or dotted-line reporting.
- Do not infer missing managers, titles, or organizational units.

## XML generation

- Use equal-sized boxes for peers and align siblings beneath their manager. Department containers must structurally contain their members when used.
- Use clean vertical/elbow or orthogonal connectors. Solid lines represent direct reporting; use dashed lines only for explicitly supported secondary reporting and explain that meaning if ambiguous.
- Keep labels concise and consistent, with role hierarchy communicated by position rather than arbitrary color changes.
